## 一、总体结论

| 维度 | 评估 |
|------|------|
| **总体匹配度** | 62/100 |
| **定制工作量** | 80-120天 |
| **实施周期** | 5-6个月 |
| **实施风险** | 中高 |

## 三、核心问题与解决方案

### 问题1：模具项目管理

**问题：** ERPNext 以"Item（库存物料）"为核心，德川以"模具项目"为核心。模具不是库存物料，是独立项目，有完整生命周期。

**解决方案：** 创建自定义 **Mold Project DocType**
- 字段：模具编号、客户、公司主体、状态、图纸关联、单据关联
- 所有业务单据（报价、订单、采购、生产、质检、送货）关联到 Mold Project
- 状态流：立项→设计→采购→生产→质检→出货→收款→完成

---

### 问题2：工程管理空白

**问题：** ERPNext 无工程设计阶段管理，无图纸版本控制，无三方确认流程。

**解决方案：** 创建三个 DocType
1. **Preparation Drawing（备料图）** - 图纸文件、版本、物料清单
2. **Formal Drawing（正式图）** - 图纸文件、版本、关联备料图
3. **Drawing Confirmation（图纸确认）** - 工程/生产/业务确认 + 客户确认

**三方确认实现：**
- ERPNext 原生 Workflow 是串行审批，不支持并行
- 方案A（推荐）：先串行审批（工程→生产→业务→客户），后期优化
- 方案B：自定义开发并行审批逻辑（工时+5-8天）

---

### 问题3：成本归集维度

**问题：** ERPNext 成本按 Item 核算，德川需要按模具项目归集成本。

**解决方案：**
1. 每个 Mold Project 关联一个 ERPNext Project
2. 采购单据关联到该 Project
3. 利用 Project Costing 归集材料成本
4. 自定义报表汇总：材料成本 + 人工成本 + 费用 = 模具总成本

---

### 问题4：试模报告

**问题：** ERPNext 的 Quality Inspection 是来料/成品检验，不是试模报告。

**解决方案：** 创建 **Trial Report DocType**
- 试模信息：日期、次数、机台、材料
- 参数记录：多组参数、标准值、判定结果
- 质量评估：外观/尺寸/功能检查
- 处理决定：出货/返工/报废

---

### 问题5：对账管理

**问题：** 德川的对账单是汇总多个送货单后与客户确认，不是 Sales Invoice。

**解决方案：** 创建 **Reconciliation Statement DocType**
- 关联客户、对账周期
- 汇总送货单明细（产品、数量、单价、金额）
- 记录客户确认状态和确认日期
- 关联后续收款计划

## 五、实施路线图

```
Phase 1 (第1-2月): 核心数据与交易流程
├── Mold Project DocType 开发
├── 客户/供应商基础数据
├── Quotation → Sales Order → 立项流程
├── 简化版采购流程
└── 验收: 能完成一个模具的完整订单流程

Phase 2 (第3-4月): 工程与生产
├── 备料图/正式图 DocType
├── 图纸确认流程
├── Work Order / Job Card 配置
├── 周计划 DocType
└── 验收: 能跟踪模具的设计和生产进度

Phase 3 (第5月): 质检与出货
├── 试模报告 DocType
├── Delivery Note 配置
├── 打印模板定制
└── 验收: 能完成模具的出货流程

Phase 4 (第6月): 财务与报表
├── 对账单 DocType
├── 收款/付款计划
├── 成本汇总报表
├── 利润分析报表
└── 验收: 能进行财务核算和报表分析
```

## 八、ERPNext 优势（为什么仍然推荐）

1. **100% 开源** - 零许可证费用，完全可控
2. **Frappe Framework** - 低代码开发，自定义 DocType 效率高
3. **基础模块成熟** - 销售/采购/库存/财务经过验证
4. **社区活跃** - 问题可在论坛找到解答
5. **长期可维护** - 不被供应商锁定
6. **成本可控** - 只需投入开发人力，无按用户收费
