## 1.2 V2.0 核心修正

### 我之前低估了什么？

1. **ERPNext 不是为 ETO（Engineer-to-Order）设计的**
   - ERPNext 官方博客明确说明支持 ETO，但实际是通过"每次创建新 BOM"来适配
   - 真正的 ETO ERP（如 Total ETO、JOBSCOPE）有专门的工程设计模块、BOM 分阶段发布、项目成本追踪
   - ERPNext 缺少：工程设计阶段管理、图纸版本控制、三方并行审批、按项目成本归集

2. **"模具项目"与"Item"的根本性差异**
   - V1.0 认为可以用 Item + 自定义字段
   - V2.0 认识到：Item 是库存概念，有数量、单价、库存金额；模具是项目概念，有状态流、成本归集、图纸关联
   - 这不是"添加字段"能解决的，需要创建独立的核心 DocType

3. **并行审批的技术难度**
   - V1.0 假设 ERPNext Workflow 可以配置三方确认
   - V2.0 发现：ERPNext Workflow 是**串行审批**，不支持原生并行审批
   - 三方确认（工程+生产+业务同时审批）需要完全自定义开发

4. **成本归集的架构差异**
   - V1.0 假设可以用 Project Costing
   - V2.0 发现：ERPNext 的成本是按 Item 核算，Project Costing 主要用于服务业
   - 按模具项目归集材料成本、人工成本、费用需要重新设计

## 模块 1: 产品/模具信息管理（核心模块）

### 初始评估回顾
- **V1.0 评分:** 70%
- **V1.0 方案:** 使用 Item DocType + 大量自定义字段

### 深度正反辩论

#### 🟢 正方论点（支持使用 ERPNext）

| 论点 | 证据 | 强度 |
|------|------|------|
| Item 支持自定义字段 | ERPNext 文档确认，可添加任意字段 | ⭐⭐⭐⭐ |
| Naming Series 支持编码规则 | 可配置 DC{YYYY}{####} 格式 | ⭐⭐⭐⭐ |
| 文件附件功能存在 | File Manager 可关联任何 DocType | ⭐⭐⭐ |
| Item Variant 可区分不同模具 | 理论上可用 | ⭐⭐ |
| 社区有制造业案例 | Frappe 博客、Medium 文章 | ⭐⭐⭐ |

#### 🔴 反方论点（质疑 ERPNext 适配性）

| 论点 | 证据 | 强度 |
|------|------|------|
| Item 是"库存物料"概念 | ERPNext 源码：Item 有 stock_uom, valuation_rate, stock_qty | ⭐⭐⭐⭐⭐ |
| 模具不走 MRP/库存 | 德川需求文档：每套模具独立项目，不存库 | ⭐⭐⭐⭐⭐ |
| 状态流不匹配 | Item 无"立项→设计→采购→生产→质检→出货→收款"状态 | ⭐⭐⭐⭐⭐ |
| 数据关联方向相反 | ERPNext: Item→BOM→WO；德川: 项目→所有单据 | ⭐⭐⭐⭐ |
| ETO 制造需要 Project 核心 | ETO ERP 行业文献：项目是核心对象 | ⭐⭐⭐⭐ |

#### 🤔 辩论升级：三种方案深度对比

**方案 A: 使用 Item + 自定义字段**

```
优点:
- 复用 ERPNext 现有功能（BOM、Work Order、Stock）
- 开发工作量最小

缺点:
- 概念强行匹配，用户认知混乱
- 每套模具都是独立 Item？Item 列表会非常长
- 模具状态如何管理？Item 没有状态流
- 模具关联的采购单、生产单如何查询？

结论: ❌ 不推荐 - 概念错位会导致长期维护困难
```

**方案 B: 使用 Project + 自定义字段**

```
优点:
- Project 概念与"模具项目"匹配
- ERPNext Project 有成本追踪功能
- 可以关联 Task、Timesheet

缺点:
- Project 主要用于服务业/咨询业，不是制造业
- 缺少产品明细（品名、规格、数量、单价）字段
- 需要大量自定义关联到销售、采购、生产单据
- 图纸管理完全缺失

结论: 🟡 部分可行 - 但需要大量定制
```

**方案 C: 创建独立的 Mold Project DocType**

```
优点:
- 完全按照德川需求设计字段和状态流
- 可以作为核心 Link Field 关联所有业务单据
- 清晰的数据模型，用户易理解

缺点:
- 开发工作量最大
- 无法直接复用 ERPNext 的部分功能
- 需要处理与 Item、BOM、Work Order 的关系

结论: ✅ 推荐 - 虽然工作量大，但是正确的架构选择
```

#### 🤔 关键问题深挖：并行审批

**德川的三方确认流程:**
```
正式图完成
    ├── 工程确认 ──┐
    ├── 生产确认 ──┼── 全部通过 → 客户确认
    └── 业务确认 ──┘
                   └── 任一拒绝 → 返回修改
```

**ERPNext Workflow 能力:**
```
状态A → 状态B → 状态C → 状态D
       (串行，不支持并行)
```

**解决方案评估:**

| 方案 | 描述 | 可行性 | 工作量 |
|------|------|--------|--------|
| 串行代替并行 | 工程→生产→业务 依次审批 | ✅ 可行 | 低 |
| 三个独立字段 | 三个确认人/时间字段，脚本判断 | ✅ 可行 | 中 |
| 自定义并行逻辑 | 开发并行审批功能 | ⚠️ 复杂 | 高 |
| 先串行后优化 | Phase 1 用串行，Phase 2 加并行 | ✅ 推荐 | 分阶段 |

#### 🤔 关键问题深挖：自动立项

**需要实现的逻辑:**
```python
# 伪代码
def on_sales_order_submit(doc):
    # 1. 生成模具编号
    mold_number = generate_mold_number(doc.company_entity, doc.transaction_date)
    # DC2025001 或 YL2025001
    
    # 2. 创建模具项目
    mold_project = frappe.new_doc("Mold Project")
    mold_project.mold_number = mold_number
    mold_project.customer = doc.customer
    mold_project.sales_order = doc.name
    mold_project.status = "立项"
    mold_project.insert()
    
    # 3. 更新销售订单关联
    doc.mold_project = mold_project.name
    doc.save()
```

**实现方式:**
- Server Script（无需代码部署）
- Custom App Hook（需要开发环境）
- Workflow + Auto Assignment（有限能力）

#### 🤔 关键问题深挖：成本归集

**ERPNext 原生成本流:**
```
Purchase Receipt → Stock Ledger Entry → Item Valuation
                                         ↓
                              Cost of Goods Sold (按 Item)
```

**德川需要的成本流:**
```
Purchase Receipt → Mold Cost Ledger → 模具项目成本汇总
    (关联模具编号)                        ↓
                              毛利计算 (销售金额 - 总成本)
```

**解决方案:**

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **方案 A: 使用 Project** | 采购单关联 Project | Project Costing 可用 | Project 不是模具项目 |
| **方案 B: 自定义成本分类账** | 创建 Mold Cost Ledger | 完全满足需求 | 开发量大 |
| **方案 C: 组合方案** | Project + 自定义报表 | 利用现有功能 | 需要流程规范 |

**推荐方案 C 详解:**
1. 每个模具项目同时创建一个 ERPNext Project
2. 采购单据关联到该 Project
3. ERPNext 自动归集成本到 Project
4. 自定义报表从 Project 汇总到 Mold Project

#### 🤔 关键问题深挖：单件生产 vs 批量生产

**批量生产（ERPNext 原生模式）:**
```
Item A: 生产 100 件
  └── BOM: 原材料 X 10kg, Y 5kg
  └── Work Order: qty=100
  └── 成品入库: 100 件 @ ¥50/件
```

**单件定制（德川模式）:**
```
模具 DC2025001: 生产 1 套
  └── 备料图 → 物料清单
  └── 多道工序: 线割→火花→磨床→组装
  └── 不入"成品库"，直接出货给客户
```

**适配策略:**
- Work Order qty=1 可用
- 工序用 Operations + Job Card
- 不使用"成品入库"，直接标记完成
- 与 Delivery Note 关联

| **成本核算维度不匹配** | ERPNext 按 Item，德川按模具项目 | ⭐⭐⭐⭐⭐ |
| 德川/裕霖分别汇总 | 需按"公司主体"筛选报表 | ⭐⭐⭐ |

#### 🤔 关键问题深挖：成本核算维度

**ERPNext 原生成本核算:**
```
Gross Profit Report 维度:
- 按 Item
- 按 Customer
- 按 Sales Person
- 按 Territory
❌ 不支持按 Project/模具项目
```

**德川需要的成本核算:**
```
模具 DC2025001 成本表:
├── 直接材料: ¥50,000 (从采购入库汇总)
├── 直接人工: ¥10,000 (从工时记录)
├── 制造费用: ¥5,000 (加工费、运费)
├── 总成本: ¥65,000
├── 销售收入: ¥100,000
├── 毛利: ¥35,000
└── 毛利率: 35%
```

**解决方案:**
1. 所有单据添加 Mold Project Link Field
2. 创建自定义成本汇总报表
3. 查询逻辑: 按 Mold Project 汇总所有关联的 Purchase Receipt、Stock Entry 金额

## 模块 8: 双公司主体管理

### 深度反思

#### V1.0 方案回顾
- 使用 ERPNext Multi-Company 功能
- 评分: 90%

#### V2.0 重新评估

**德川实际需求:**
- 德川/裕霖是同一法人的两个品牌
- 对外签约、开票用不同名称
- 对内统一管理，不需要独立核算

**ERPNext Multi-Company:**
- 用于真正的多公司独立核算
- 支持 Inter-Company Transactions
- 每个 Company 有独立的 Chart of Accounts

**结论:**
Multi-Company 是**过度设计**，用简单的 Custom Field "公司主体"(德川/裕霖) 更合适。

| **双公司管理综合** | 90% | **85%** | 方案调整，实际更简单 |

## 4.2 最终建议

### ✅ 条件性推荐 ERPNext

**必要条件（缺一不可）:**

1. **实施团队能力**
   - 至少 2 名熟悉 Frappe/ERPNext 的开发人员
   - 至少 1 名有制造业 ERP 经验的顾问
   - 内部需要 1 名 IT 负责人全程参与

2. **预算准备**
   - 开发费用：80-120 人天 × 单价
   - 培训费用：6-8 人天
   - 上线后支持：3-6 个月

3. **时间预期**
   - 至少 5-6 个月实施周期
   - 分阶段上线，不要一步到位

4. **流程妥协**
   - 接受先串行审批后优化为并行
   - 接受先简化成本核算后完善
   - 接受部分功能 Phase 2 实现

### ⚠️ 如果不满足条件

**替代方案评估:**

| 方案 | 优点 | 缺点 | 适合情况 |
|------|------|------|---------|
| **Odoo Enterprise** | 功能更全，有专业制造模块 | 按用户收费，有成本 | 预算充足，快速上线 |
| **专业 ETO ERP** | 完美匹配 ETO 制造 | 很贵，学习曲线陡 | 大规模定制制造 |
| **简化版 ERPNext** | 先用核心功能 | 部分手工处理 | 预算有限，先跑起来 |
| **继续 Excel** | 无成本 | 问题依旧 | 暂缓 ERP 实施 |

## 4.3 分阶段实施建议

```
Phase 1 (第1-2月): 核心交易流程
├── Mold Project DocType
├── 客户/供应商基础数据
├── Quotation → Sales Order → 立项
├── 简化版采购流程
└── 验收: 能完成一个模具的完整订单流程

Phase 2 (第3-4月): 工程与生产
├── 备料图/正式图 DocType
├── 图纸确认流程（串行）
├── Work Order / Job Card 配置
├── 周计划（简化版）
└── 验收: 能跟踪模具的设计和生产进度

Phase 3 (第5月): 质检与出货
├── 试模报告 DocType
├── Delivery Note 配置
├── 打印模板
└── 验收: 能完成模具的出货流程

Phase 4 (第6月): 财务与报表
├── 对账单 DocType
├── 收款/付款计划
├── 成本汇总报表
├── 利润分析报表
└── 验收: 能进行财务核算和报表分析

Phase 5 (持续): 优化迭代
├── 三方确认优化为并行
├── 人工成本归集
├── 移动端适配
└── 更多自动化
```
