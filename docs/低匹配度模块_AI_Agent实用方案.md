# 低匹配度模块 AI Agent 实用方案
# 德川/裕霖业务管理系统

> **设计原则:** 简单、实用、工人能用  
> **每个模块一个核心Agent，解决一个关键痛点**

---

## 一、产品/模具管理 Agent

### 痛点
老板/业务员想知道某个模具进度，要打电话问生产、问工程、问采购，信息分散。

### 解决方案：进度查询 Agent

**使用场景：**
```
业务员在企业微信发消息:
"DC2025018 什么进度？"

Agent 回复:
━━━━━━━━━━━━━━━━━━━━━━━
DC2025018 进度查询
客户: 美的
━━━━━━━━━━━━━━━━━━━━━━━
当前状态: 生产中

✓ 立项      01-05 完成
✓ 图纸确认  01-10 完成  
✓ 物料到齐  01-15 完成
▶ 生产中    线割完成，火花机进行中
○ 质检      待开始
○ 出货      计划 01-28

预计交期: 01-28 (还剩8天)
风险提示: 无
━━━━━━━━━━━━━━━━━━━━━━━
```

**也支持批量查询：**
```
"美的的模具都什么进度？"
"这周要交的模具有哪些？"
"哪些模具物料还没到齐？"
```

### 实现方式

| 组件 | 方案 |
|------|------|
| 入口 | 企业微信机器人 |
| 理解 | 简单关键词匹配 + AI理解 |
| 数据 | 查询ERPNext Mold Project |
| 输出 | 文字消息 |

### 开发工作量

| 工作项 | 工时 |
|--------|------|
| 企业微信机器人接入 | 2天 |
| 查询逻辑开发 | 3天 |
| 常用问题模板 | 1天 |
| **合计** | **6天** |

### 价值
- 老板随时掌握进度，不用到处问
- 业务员能快速回复客户询问
- 不用学新系统，在微信里问就行

## 二、工程管理 Agent

### 痛点
图纸确认环节经常卡住，工程做完了等生产确认，生产确认了等业务，业务确认了等客户。每个环节都要人去催，催不动就延期。

### 解决方案：确认催办 Agent

**工作逻辑：**
```
每天早上9点自动检查:
    ↓
找出所有"待确认"的图纸
    ↓
计算每个环节停留了多久
    ↓
超过阈值的，自动发提醒
```

**提醒规则：**

| 确认环节 | 阈值 | 提醒对象 |
|---------|------|---------|
| 工程确认 | 超过4小时 | 工程负责人 |
| 生产确认 | 超过8小时 | 生产主管 |
| 业务确认 | 超过8小时 | 对接业务员 |
| 客户确认 | 超过2天 | 业务员（催客户） |

**提醒消息示例：**
```
━━━━━━━━━━━━━━━━━━━━━━━
【图纸确认提醒】
━━━━━━━━━━━━━━━━━━━━━━━
DC2025018 正式图待您确认
客户: 美的
已等待: 12小时

请尽快处理，以免影响交期
点击查看: [链接]
━━━━━━━━━━━━━━━━━━━━━━━
```

**升级提醒（超过2倍阈值）：**
```
━━━━━━━━━━━━━━━━━━━━━━━
【紧急】图纸确认超时
━━━━━━━━━━━━━━━━━━━━━━━
DC2025018 生产确认已超时
已等待: 24小时（正常应8小时内）

已抄送: 生产经理
请立即处理！
━━━━━━━━━━━━━━━━━━━━━━━
```

### 每日汇总（发给管理层）

```
━━━━━━━━━━━━━━━━━━━━━━━
【图纸确认日报】2025-01-20
━━━━━━━━━━━━━━━━━━━━━━━
今日待确认: 5 套
  - 工程确认: 1 套
  - 生产确认: 2 套  
  - 业务确认: 1 套
  - 客户确认: 1 套

超时未确认: 2 套 ⚠️
  - DC2025018 生产确认 (24小时)
  - DC2025015 客户确认 (3天)

本周确认效率:
  平均确认时长: 18小时
  按时完成率: 85%
━━━━━━━━━━━━━━━━━━━━━━━
```

### 开发工作量

| 工作项 | 工时 |
|--------|------|
| 定时任务配置 | 1天 |
| 超时检测逻辑 | 2天 |
| 消息模板 | 1天 |
| 日报生成 | 1天 |
| **合计** | **5天** |

### 价值
- 不用人去催，系统自动催
- 管理层知道卡在哪个环节
- 数据积累后可以优化流程

## 三、质量管理 Agent

### 痛点
同样的加工问题反复出现。老师傅知道某类模具容易出什么问题，但这些经验没有传承，新人还是会犯同样的错。

### 解决方案：生产经验提醒 Agent

**工作逻辑：**
```
生产计划下发时触发:
    ↓
根据模具特征匹配历史相似模具
    ↓
查找这些模具生产时记录的问题
    ↓
生成《加工注意事项》
    ↓
随图纸一起发到车间
```

**匹配维度：**
- 客户（同客户的模具往往有类似要求）
- 模具类型（注塑模/压铸模）
- 穴数
- 材质
- 尺寸范围

**输出示例：**
```
═══════════════════════════════════════════
加工注意事项
模具: DC2025018 | 客户: 美的
═══════════════════════════════════════════

以下问题曾在类似模具上出现过，请注意避免:

【线割工序】
⚠ DC2024035: 镶件配合过紧
  原因: 补偿量0.02太大
  ✓ 建议: 补偿量用0.015

【火花机工序】
⚠ DC2024012: 放电纹粗糙  
  原因: 电流过大
  ✓ 建议: 精加工电流≤3A

【抛光工序】
⚠ DC2024035: 分型面漏抛
  原因: 标注不清
  ✓ 建议: 重点检查分型面

═══════════════════════════════════════════
来源: 3套相似模具的生产记录
有疑问联系工程部
═══════════════════════════════════════════
```

### 问题如何积累

**简单的问题登记表（车间填写）：**

| 字段 | 示例 |
|------|------|
| 模具编号 | DC2024035 |
| 工序 | 线割 / 火花 / 磨床 / 抛光 / 组装 |
| 问题描述 | 镶件配合过紧 |
| 原因 | 补偿量设置太大 |
| 解决方法 | 补偿量改成0.015 |
| 登记人 | 张师傅 |

**不需要复杂操作，就是一张简单表单。**

### 开发工作量

| 工作项 | 工时 |
|--------|------|
| 问题登记DocType | 2天 |
| 相似模具匹配逻辑 | 2天 |
| 注意事项生成 | 1天 |
| 与生产计划集成 | 1天 |
| **合计** | **6天** |

### 价值
- 老师傅的经验沉淀成数据
- 新人不会重复犯错
- 车间拿到的是纸，不用学系统

## 四、财务管理 Agent

### 痛点
- 该收的款催不回来，账期过了才发现
- 哪个模具赚了亏了，算不清楚

### 解决方案：收款提醒 Agent

**工作逻辑：**
```
每天检查:
    ↓
找出所有应收账款
    ↓
根据客户账期计算到期日
    ↓
提前提醒 + 到期提醒 + 超期预警
```

**提醒规则：**

| 阶段 | 提醒时间 | 提醒对象 |
|------|---------|---------|
| 提前提醒 | 到期前7天 | 业务员 |
| 到期提醒 | 到期当天 | 业务员 + 财务 |
| 超期预警 | 超期3天 | 业务员 + 财务 + 业务经理 |
| 严重超期 | 超期15天 | 抄送总经理 |

**提醒消息示例：**
```
━━━━━━━━━━━━━━━━━━━━━━━
【收款提醒】
━━━━━━━━━━━━━━━━━━━━━━━
客户: 美的
对账单: DZ2025-0018
金额: ¥85,000
到期日: 2025-01-25（还剩5天）

请提前联系客户确认付款安排
━━━━━━━━━━━━━━━━━━━━━━━
```

**超期预警：**
```
━━━━━━━━━━━━━━━━━━━━━━━
```

## 五、汇总

### 四个Agent一览

| 模块 | Agent名称 | 核心功能 | 工时 |
|------|----------|---------|------|
| 产品/模具管理 | 进度查询 | 微信问进度，即时回复 | 6天 |
| 工程管理 | 确认催办 | 自动催确认，超时预警 | 5天 |
| 质量管理 | 经验提醒 | 历史问题随图纸下发 | 6天 |
| 财务管理 | 收款提醒 | 到期催收，超期预警 | 7天 |
| **合计** | - | - | **24天** |

### 匹配度提升

| 模块 | 纯ERPNext | +AI Agent | 提升 |
|------|----------|-----------|------|
| 产品/模具管理 | 45% | **60%** | +15% |
| 工程管理 | 20% | **40%** | +20% |
| 质量管理 | 25% | **45%** | +20% |
| 财务管理 | 56% | **70%** | +14% |

### 实施优先级建议

```
第一批（最快见效）:
├── 进度查询Agent（老板最关心）
└── 收款提醒Agent（直接影响现金流）

第二批（流程优化）:
├── 确认催办Agent（解决卡点）
└── 经验提醒Agent（需要积累数据）
```

### 设计原则

1. **入口简单** - 企业微信问一句话就行
2. **输出简单** - 文字消息或打印纸张
3. **不改变习惯** - 系统主动推送，不用人去查
4. **解决真问题** - 每个Agent只解决一个痛点
